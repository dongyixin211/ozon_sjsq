## 后端架构重构方案设计

用户请求对 `server/` 后端工程进行架构重构，提升扩展性和稳定性。

### 现状分析
- 技术栈: Fastify 4 + PostgreSQL 16 + Redis + Cloudflare R2 + Sharp + Zod
- 代码量: ~14,728 行，核心问题: gallery-routes.ts 达 5,712 行
- 入口 index.ts 和 gallery-routes.ts 都有 @ts-nocheck
- 无服务层/仓储层分层，路由中混合验证+逻辑+SQL+存储
- 异步任务用进程内 Map/Set 管理，重启即丢
- 单进程部署，无法水平扩展

### 设计方案
- 分层+模块化架构: routes → controller → service → repository
- 8 个领域模块: auth/gallery/mockup/listing/shop/order/ai/task
- 核心层 core/ 统一管理横切关注点
- 基础设施层 infrastructure/ 管理存储/缓存/队列/HTTP
- 引入 Kysely 替代裸 SQL，BullMQ 替代进程内状态，熔断器保护外部调用
- 4 阶段迁移: 骨架搭建 → 模块拆分 → 任务队列 → 可观测性
- 完整方案文档: docs/backend-architecture-refactor-plan.md
