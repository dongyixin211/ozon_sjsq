# 商业版云图库与会员后端设计

## 已落地的第一版骨架

项目新增了 `server` 目录，作为独立云端后端。当前方向已经调整为“网页版工作台 + 客户端本地助手”：

- 用户主要打开浏览器里的工作台操作账号、会员、云图库和后续任务入口。
- 客户端继续负责本机 Excel、图片目录、订单文件、Ozon 密钥等浏览器不能直接处理的能力。
- 云后端统一校验会员、设备绑定、图库使用记录，并托管网页版入口。

核心边界：

```text
浏览器工作台
  -> 登录你的云后端
  -> 云后端校验会员、设备、图库使用记录
  -> 云后端连接 Cloudflare R2 / Backblaze B2
  -> 如需本机文件能力，再调用 127.0.0.1 本地助手
```

这样做的原因很关键：R2/B2 Secret 不能放在 exe 里，否则别人可以反编译拿到密钥。

另一个关键原因是浏览器不能直接读写用户电脑里的任意目录。批量上架、Excel 读取、图片批处理、订单 PDF 保存等能力仍然需要客户端承担。

## 当前访问地址

线上入口：

```text
用户工作台：https://api.dyxtoolai.cn/app/
管理员后台：https://api.dyxtoolai.cn/admin
健康检查：https://api.dyxtoolai.cn/health
```

桌面客户端启动后，会在本机开放只读健康检查：

```text
http://127.0.0.1:17641/health
```

第一版只返回客户端状态、版本和设备指纹，用于网页登录时复用同一台机器的设备绑定。后续如果要让网页触发本地 Excel/图片/Ozon 任务，必须增加一次性连接码和来源校验。

## 当前接口范围

### 账号与会员

- `POST /auth/register`：手机号 + 密码注册
- `POST /auth/login`：手机号 + 密码登录
- `GET /me`：查询当前账号与会员状态
- `POST /license/redeem`：兑换授权密钥
- `POST /auth/logout`：退出登录

### 管理员

- `POST /admin/license-keys`：批量生成授权密钥
- `GET /admin/users`：查看用户
- `POST /admin/users/:userId/unbind-device`：解绑用户设备

### 店铺

- `GET /shops`：查看当前账号同步过的店铺
- `POST /shops/upsert`：同步桌面端店铺到云端

### 云图库

- `GET /gallery/assets`：查询图库，支持比例筛选和隐藏已使用货号
- `POST /gallery/assets/upload`：上传图片到云端图库
- `POST /gallery/assets/:assetId/use`：标记某店铺已使用图片

### 网页托管

- `GET /app/`：用户工作台
- `GET /app/assets/*`：用户工作台静态资源

## 需要你准备的线上资源

1. Cloudflare 账号
2. R2 Bucket
3. R2 API Token
4. 一个用于图片访问的域名，例如 `img.你的域名.com`
5. 一个用于后端接口的域名，例如 `api.你的域名.com`
6. 阿里云 ECS 登录方式
7. PostgreSQL 数据库
8. HTTPS 证书

## 风险提醒

当前第一版是可开发、可部署的骨架，不是最终商业闭环。已经具备网页登录、会员、云图库和本地助手探测，但发布商品、更新商品、更新库存、订单下载等本地任务还没有全部改成网页按钮调用本地助手。

下一步建议优先做三件事：

1. 给本地助手增加一次性连接码，防止未知网页调用本机能力。
2. 将“店铺同步”从手动填写改成客户端自动同步。
3. 按风险从低到高，把查询仓库、查询商品、更新库存、批量上架逐步接到网页端。

更进一步的商业化建议是做一个简单管理后台，用来：

- 批量生成授权密钥
- 查询用户会员到期时间
- 解绑设备
- 查看图库上传量
- 查看用户使用记录
- 后续接入自动支付
