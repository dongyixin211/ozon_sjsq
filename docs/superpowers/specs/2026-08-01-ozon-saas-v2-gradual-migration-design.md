# Ozon SaaS V2 渐进迁移设计

## 决策

在当前仓库原地推进 V2，但不整体替换正在使用的旧功能。旧云端接口、本地 Ozon 核心和网页页面继续可用；V2 使用独立数据库表、`/api/v2` 路由和独立前端入口，按业务模块切换。

## 首期范围

1. 用户与许可证映射到单一租户，所有 V2 查询和写入必须带 `tenant_id`。
2. 一次性设备配对码、可撤销设备令牌、助手心跳与在线状态。
3. 不含 Ozon 密钥的店铺镜像。
4. `(tenant_id, sku)` 唯一的商品主档、店铺分配与事务性 SKU 预留。
5. 任务创建、设备原子领取、租约续期、进度回传、取消与恢复查询。
6. 仅将 Excel 成品图上架接入 V2 任务协议；实际 Ozon 请求继续由 Windows 助手执行。

## 兼容与安全

- 旧路由和旧数据不修改、不删除；V2 不读取或迁移 Ozon API Key、网盘 Cookie、原始图片和套图成品到云端。
- V2 API 拒绝缺失租户上下文的请求；管理员不能默认读取本地凭证或文件。
- SKU 预留只有取消、前置校验失败或显式释放才可撤销；已提交 Ozon 的 SKU 不自动改分配。
- 任务状态使用 `draft`、`queued`、`claimed`、`preparing`、`processing`、`submitting`、`succeeded`、`partial_failed`、`failed`、`waiting_quota`、`cancelled`。

## 发布阶段

第一阶段交付租户、设备、店铺镜像、SKU 和任务协议；第二阶段接入 Excel 成品图上架并以 1–3 SKU/店铺灰度；第三阶段接入自动套图、AI 中转与额度控制；最后迁移商品维护、订单、活动和浏览量。

## 验收

- 不同租户无法读取、修改或领取对方的店铺、SKU、任务和设备。
- 同租户并发创建相同 SKU 时只允许一次预留。
- 助手重启后不重复提交已发往 Ozon 的请求。
- 旧页面继续工作；V2 入口只操作 V2 数据。
