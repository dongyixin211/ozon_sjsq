# 本地自动上品与批次任务中心设计

## 1. 目标

用户上传图片时只选择商品类型。系统根据已保存的上架方案，自动确定样机、标题提示词、商品模板和目标店铺，并在每日执行窗口内由本地助手按 Ozon 实际额度完成套图、标题生成和商品提交。

必须满足：

- 不需要每天重复选图和配置模板。
- 一张原图全局只能分配给一个店铺。
- 不全量处理一万多张图片，只加工当天计划和少量缓冲。
- 同品类店铺默认平均分配。
- 客户端关闭时暂停，重启后继续且不重复提交。
- Ozon 密钥、套图、标题和提交继续由本地助手执行。

## 2. 范围

本期包括上架方案向导、Ozon 上传额度查询、本地每日调度、图片唯一锁定、小批次按需加工、上传中批次任务视图、失败恢复和一致性测试。

本期不包括云端执行上架、客户端关闭后继续运行、根据销量自动调整品类权重、自动删除 Ozon 商品和全量预生成样机。

## 3. 总体架构

复用现有图库、上架偏好、云端上架批次和本地 `auto_listing` 任务，不创建第二套上架执行器。

新增三个组件：

1. **上架方案**：保存商品类型到样机、标题提示词、商品模板和店铺的映射。
2. **本地自动调度器**：查询额度、生成计划、锁定图片并启动现有本地任务。
3. **批次任务中心**：按批次展示进度、错误和恢复操作。

数据流：

`上传并选择商品类型 → 未分配图库 → 本地读取 Ozon 额度 → 云端原子锁定图片 → 本地按批套图和生成标题 → 提交 Ozon → 回写状态`

## 4. 上架配置方案

每个启用方案包含：

- 方案名称和商品类型 `productImageRuleId`。
- 样机模板。
- 标题提示词模板和提示词快照。
- 每个店铺的本地店铺 ID、云端店铺 ID、商品模板和模板快照。
- 执行窗口，默认 `08:00–22:00`。
- 单批数量，默认 10，允许 5–20。
- 滚动缓冲，默认 20，最多两个批次。
- 是否启用自动执行。

一个商品类型同一时间只能有一个启用方案，避免多个方案竞争同一图片。

配置向导分四步：商品类型与内容模板、目标店铺与商品模板、调度设置、配置检查。检查内容包括商品类型、样机、提示词、店铺密钥、商品模板、仓库和本地助手能力。

## 5. Ozon 额度查询

本地 `OzonSellerClient` 增加 `ProductAPI_GetUploadQuota` 查询，按当前官方接口调用 `POST /v4/product/info/limit`，并兼容新增或缺失字段。

每个店铺保存每日可创建总量和剩余量、每日可更新总量和剩余量、商品总容量和剩余容量、操作级限额、最近刷新时间和错误。

字段缺失时不能使用一个很大的默认值。创建额度或容量未知时，该店铺本轮不自动分配。

可计划数量：

`min(创建剩余额度 - 安全预留, 商品容量剩余, 未分配图片数)`

安全预留默认取创建剩余额度的 5%，且至少保留 2 个名额。剩余额度不足 3 时本轮不创建任务。

## 6. 图片选择和平均分配

候选图片必须与方案商品类型一致、未删除、未上架、未归属店铺、未被其他计划锁定且不在异常隔离状态。

图片按上传时间从早到晚选择，相同时间按图片 ID 稳定排序。

同品类店铺使用额度感知的轮询平均分配：

1. 排除额度未知、容量不足、禁用或配置不完整的店铺。
2. 每轮依次给每个可用店铺分配一张。
3. 店铺达到自身额度后退出本轮。
4. 剩余图片继续平均分配给其他店铺。

## 7. 图片唯一归属

图片分配必须由云端数据库原子完成，不能由前端先读后写。

分配记录包含图片、方案、目标店铺、计划、批次、状态、锁定时间、错误和重试次数。数据库对有效分配建立图片 ID 唯一约束，保证一张图片只有一个未释放或已完成的归属。

状态包括 `reserved`、`preparing`、`ready`、`submitting`、`completed`、`failed`、`paused` 和 `released`。

`completed`、`failed` 和 `paused` 都保留店铺归属。只有明确执行“释放图片”后才能重新分配。

## 8. 本地自动调度器

本地助手启动后立即恢复未完成任务；执行窗口内每 10 分钟检查是否需要补充批次；日期变化后重新读取额度；网络恢复、限流等待结束或人工继续时立即复查。

同一账号同一时间只允许一个调度循环生成计划。

每个方案最多保持一个执行批次、一个等待批次和两个批次大小的候选缓冲。缓冲只预留图片，不提前套图或生成标题。

批次复用现有流程：读取配置快照、套图、生成缺失标题、创建云端上架批次、调用 `start_auto_listing`、回写每张图片和店铺结果。

## 9. 批次任务中心

上传中页面改为批次主视图，顶部显示今日计划、等待处理、套图和标题处理中、提交 Ozon、已完成和失败待处理数量。

每个批次显示品类、方案、批次编号、各店铺分配数、当前阶段、完成数、失败数、预计剩余时间、额度快照和最近错误，并提供暂停、继续、只重试失败项、查看图片和日志。

图片列表作为批次展开明细。图库分页总数不得作为自动任务数量。

## 10. 失败与恢复

- 单张套图或标题最多自动重试 3 次，失败不阻塞同批其他图片。
- Ozon 限流时优先使用返回的等待信息，否则指数退避，最长 30 分钟。
- 鉴权失败、模板缺失或额度未知只暂停对应店铺。
- 客户端异常退出后，根据云端阶段和本地任务记录恢复。
- “只重试失败项”保持原店铺归属。
- “跳过”保持归属并停止自动重试。
- “释放图片”必须二次确认。
- “停止方案”只停止新批次。
- “停止并释放未开始项”只能释放尚未产生样机、标题或 Ozon 请求的 `reserved` 图片。

## 11. 数据一致性

- 云端分配记录是图片归属的唯一权威来源。
- 计划使用账号、方案、日期和序号组成幂等键。
- Ozon 提交项使用稳定的图片 ID、店铺 ID 和批次 ID。
- 阶段完成后必须回写云端；回写失败时保留本地待同步事件并重试。
- 每次补充批次前重新查询额度。
- 人工上架和自动上架共用图片唯一归属检查。

## 12. 页面结构

### 上架方案页面

展示方案品类、样机、标题模板、店铺数、执行窗口和启用状态，并提供新建向导、编辑、检查配置、暂停和手动执行一次。

### 图片上传页面

只要求选择商品类型和图片。显示该类型绑定的方案摘要；没有启用方案时允许上传，但提示不会自动上品。

### 批次任务中心

提供今日总览、方案/店铺/状态筛选、批次卡片、图片明细、失败项和额度异常入口。

## 13. 测试验收

单元测试覆盖额度新旧格式、安全预留、平均分配、唯一归属、时间窗口、缓冲限制和状态转换。

集成测试覆盖：

- 两个调度器同时请求时一张图片只能分配一次。
- 客户端退出并重启后不重复套图、标题和提交。
- 额度减少后只缩减未开始批次。
- 一个店铺鉴权失败时其他店铺继续。
- 人工和自动流程竞争同一图片时只有一个流程获得归属。

端到端验收要求：上传时只选择商品类型；无需每日手动选图；图片不会跨店重复；一万张图片不会被一次性加工；任务可按批次查看和恢复；客户端重启后从原阶段继续。

## 14. 分阶段实施

### 第一阶段：配置与额度

- Ozon 上传额度查询。
- 上架方案数据和配置向导。
- 店铺额度、容量和配置完整性展示。

### 第二阶段：分配与调度

- 图片唯一归属和原子锁定。
- 本地时间窗口调度、平均分配和滚动缓冲。
- 复用现有批次和 `start_auto_listing` 链路。

### 第三阶段：批次任务中心

- 上传中改为批次主视图。
- 失败项、暂停、继续、只重试失败项和释放规则。
- 自动任务自检和一致性检查。

## 15. 成功标准

- 配置一次后连续七天无需人工选图或重复设置模板。
- 自动计划不超过 Ozon 可用创建额度和商品容量。
- 图片跨店重复使用数量为零。
- 每个方案最多保留约两个批次的待加工图片。
- 客户端任意阶段退出并重启不产生重复商品。
- 所有新增测试和构建通过后才发布。
