# Ozon SJSQ 前端整体视觉改造设计

日期：2026-07-29  
状态：待用户确认  
采用技能：`redesign-existing-projects`（Taste Skill）

## 1. 背景与目标

当前项目是 React 18 + Vite + Tauri/Web 双端应用，使用原生 CSS 和 `lucide-react`。前端业务功能已经较完整，但全局样式文件约 5,249 行，存在大量重复覆盖和硬编码颜色，界面整体呈现为常见的默认蓝灰后台，品牌辨识度、层级一致性和交互完成度仍有提升空间。

本次改造目标是在不改变业务流程、不迁移框架、不引入大型 UI 库的前提下，只对网页端工作台进行统一视觉升级：

- 建立一致、可复用的蓝灰设计令牌。
- 提升桌面端后台的专业感、清晰度和长期使用舒适度。
- 统一侧边栏、标题栏、卡片、表格、表单、按钮、标签、弹窗和状态反馈。
- 保留现有用户的操作习惯，避免大幅改变信息架构。
- 保持 Tauri 客户端现有后台状态页完全不变。

## 2. 已确认的视觉方向

用户已确认采用：

- 视觉方案：**保守精修 · 清晰蓝灰**。
- 目标设备：以 **1440px 桌面端后台** 为主要设计基准。
- 信息密度：采用 **标准密度**，表格、表单和卡片兼顾单屏信息量与长时间使用舒适度。
- 布局方式：左侧固定完整导航，右侧主内容随窗口扩展。

该方向保留当前产品熟悉感，不采用黑绿高对比、重玻璃拟态、强渐变或大幅非对称布局。

## 3. 设计原则

### 3.1 简单优先

- 沿用 React、原生 CSS 和现有组件结构。
- 不引入 Tailwind、Ant Design、MUI 等新 UI 框架。
- 不为单次使用场景建立复杂抽象。
- 优先通过设计令牌和共享类解决重复问题。

### 3.2 精准修改

- 业务请求、状态管理、Tauri 命令和云端接口保持不变。
- 本次修改范围限定在网页端使用的 `src/App.tsx` 非 Tauri 分支及其网页工作台样式。
- `LocalAssistantShell`、Tauri 客户端状态页、客户端更新和本地助手连接页不做视觉改造。
- 页面路由、导航分组和主要操作位置原则上保持不变。
- 不顺手重构与视觉改造无关的业务代码。
- 仅当现有 DOM 结构阻碍统一样式或无障碍能力时，做最小 JSX 调整。

### 3.3 可验证

- 每个阶段先覆盖共享组件，再验证代表性页面。
- 桌面端以 1440×900 为基准，同时验证 1280px、900px 和 560px 断点。
- 每轮修改运行相关测试、完整测试和生产构建。
- 对登录页、工作台、表格页、复杂图库页和弹窗进行浏览器截图对比。

## 4. 视觉系统

### 4.1 字体

不依赖外部网络字体，避免 Tauri 离线环境和国内网络加载问题。字体栈采用：

```css
font-family: "Segoe UI Variable", "PingFang SC", "Microsoft YaHei UI", system-ui, sans-serif;
```

- 正文：13px，常规字重 400。
- 辅助文字：12px，颜色降低但保持可读对比度。
- 页面标题：22px，字重 650，轻微负字距。
- 分区标题：15–16px，字重 600。
- 数据数字：启用 `font-variant-numeric: tabular-nums`。
- 长说明文字限制阅读宽度，并使用更舒适的行高。

### 4.2 色板

主色保持蓝色，但降低过度鲜艳感，统一使用冷灰体系：

- 主色：`#2874ea`。
- 主色悬停：`#1f63ce`。
- 主色浅底：`#eaf2ff`。
- 页面背景：`#f4f7fa`。
- 一级表面：`#ffffff`。
- 二级表面：`#f8fafc`。
- 主文字：`#1d2b3e`。
- 次文字：`#526174`。
- 弱文字：`#7b899a`。
- 默认边框：`#e1e7ee`。
- 强边框：`#d6dee8`。
- 成功、警告、危险分别保持绿色、琥珀色、红色，但降低饱和度并统一浅色背景。

实施时把核心颜色、圆角、阴影、间距和层级集中到 `:root` 变量。已有页面特有颜色只有在表达业务语义时保留。

### 4.3 圆角与阴影

- 按钮、输入框：7–8px。
- 导航项：8px。
- 卡片、面板：12px。
- 大弹窗：14px。
- 药丸标签：999px，仅用于状态、筛选和短标签。
- 面板阴影保持轻量，并统一偏冷色，不使用明显黑色浮层。

### 4.4 间距与密度

采用 4px 基础间距体系，主要间距为 8、12、16、20、24、32px。

- 桌面主内容内边距：20–24px。
- 面板内容内边距：14–16px。
- 标准表格行高：48–54px，复杂信息行可适当增加。
- 输入框和按钮高度：34–36px。
- 页面标题区域与正文间距：16–20px。

## 5. 页面壳层

### 5.1 左侧导航

- 桌面宽度由当前 216px 微调为约 216–224px。
- 品牌区显示 `Ozon SJSQ` 和简短产品说明。
- 导航保留现有分组和层级，不重新定义产品信息架构。
- 当前项使用浅蓝底、深蓝文字和中等字重，不使用大面积高饱和色。
- 图标统一使用现有 `lucide-react`，保持相同尺寸和描边宽度。
- 底部账号、授权或版本信息形成独立区域。

### 5.2 顶部区域

- 页面标题左对齐，辅助信息置于标题上方或下方。
- 页面级主要操作放在右侧，按钮数量超过三个时区分主次或进入更多菜单。
- 不新增固定全局顶栏，避免改变现有页面结构；优先升级已有 `.topbar`。

### 5.3 主内容区

- 宽屏内容最大宽度保持当前约 1680px 的能力，但增加统一的水平居中与呼吸空间。
- 页面采用 12 列网格或明确的 CSS Grid，不使用复杂百分比计算。
- 面板根据内容自然高度展示，不强制所有卡片等高。

## 6. 共享组件规范

### 6.1 按钮

- 主按钮：蓝底白字，用于每个区域唯一的主要动作。
- 次按钮：白底灰边框，用于普通操作。
- 危险按钮：浅红底和红色文字，仅用于不可逆操作。
- 图标按钮必须具备可见悬停、键盘焦点和禁用状态。
- 所有按钮避免布局位移，悬停仅改变色彩、边框和轻微阴影。

### 6.2 表单

- 输入框、选择框和文本域统一高度、边框、圆角和焦点环。
- 标签与控件垂直排列，帮助文字和错误信息位置固定。
- 必填、错误、禁用、只读和加载状态必须视觉明确。
- 不改变现有字段、校验和提交逻辑。

### 6.3 面板与卡片

- 使用白色表面、冷灰边框和轻阴影建立层级。
- 面板头部统一为标题、说明、右侧操作三区结构。
- 避免每个普通文本块都做成浮动卡片；只为真实分组提供边界。

### 6.4 表格

- 表头使用浅灰背景和弱化文字。
- 行高采用标准密度，行悬停使用极浅蓝灰。
- 数字列启用等宽数字并保持右对齐或稳定对齐。
- 状态以语义标签展示，操作列保持固定宽度。
- 宽表格继续使用横向滚动，不强行压缩到不可读。

### 6.5 状态与反馈

- 成功、警告、错误、处理中状态使用一致颜色和图标。
- 补齐关键页面的加载、空数据和错误状态视觉。
- 保留现有消息内容和触发逻辑，仅升级呈现方式。
- 动画控制在 120–180ms，并支持 `prefers-reduced-motion`。

### 6.6 弹窗

- 遮罩、容器、标题、正文和操作区统一。
- 桌面端居中，窄屏靠上并保留安全边距。
- 危险确认突出后果，不用颜色之外的单一信号表达状态。

## 7. 网页端页面范围

本次改造覆盖网页端工作台及其可见业务页面：

- 网页端登录、注册、授权和同步门禁页面。
- 应用壳层、侧边栏、页面标题和全局提示。
- 工作台与数据概览。
- 商品管理。
- 素材管理和上传工作台。
- 订单查询与订单操作。
- 自动刊登计划和任务中心。
- 云图库及其复杂表格、筛选、弹窗和批量操作。
- 店铺、会员、许可证、设置、作业日志等辅助页面。
- 网页端入口、网页侧边栏和网页工作台。

明确不包含客户端截图中的以下页面：本地助手运行状态、浏览器工作台连接状态、客户端 API 地址、客户端版本检测、打开浏览器工作台和重新检测按钮。

## 8. 响应式行为

- `>= 1200px`：完整桌面布局，固定侧边栏，多列内容区。
- `901–1199px`：侧边栏保持可用，内容列数适度减少。
- `561–900px`：壳层转为单列，导航变为顶部或可换行区域，表格保留横向滚动。
- `<= 560px`：表单和操作按钮单列展示，弹窗占据大部分宽度。

移动端目标是保持可用，不另行设计一套独立移动产品，也不把桌面表格错误地压缩成卡片列表，除非现有页面已经采用该模式。

## 9. 实施边界

### 包含

- 重整 `src/styles.css` 的设计令牌和共享基础样式。
- 对 `src/App.tsx` 和必要页面做小范围语义结构与 class 调整。
- 清理由本次改造取代的重复样式和覆盖规则。
- 更新与视觉结构直接相关的组件测试。
- 增加必要的无障碍属性、焦点样式和减少动效支持。

### 不包含

- 后端、数据库、云服务和 Tauri Rust 逻辑改动。
- Tauri 客户端 `LocalAssistantShell` 及其状态页的任何视觉或交互改动。
- API 字段、业务流程、权限模型和路由体系调整。
- 新增暗色模式。
- 新增换肤、主题编辑器或用户可配置密度。
- 全面重写 `GalleryManager.tsx` 等大型业务组件。
- 为追求风格而引入图片、远程字体或额外动画库。

## 10. 分阶段实施建议

1. **基础令牌与壳层**：字体、色板、背景、导航、顶部区域、焦点样式。
2. **共享控件**：按钮、表单、标签、面板、表格、弹窗、状态。
3. **入口页面**：登录、授权、工作台，建立视觉基线。
4. **核心业务页**：商品、素材、订单、自动刊登和任务中心。
5. **复杂页面**：云图库及其批量操作、长表格和弹窗。
6. **响应式与收尾**：各断点、空状态、错误状态、减少动效和一致性清理。

每一阶段都应保持可运行、可测试和可回退，避免一次性重写 5,000 多行样式。

## 11. 验收标准

- 网页端登录页和主应用壳层与已确认的清晰蓝灰桌面方案一致。
- 1440px 下侧边栏、标题区、四列数据卡片、宽表格和辅助面板层级清晰。
- 主要页面不再出现明显不一致的按钮高度、边框、圆角和状态颜色。
- 表格、表单、弹窗在标准密度下可读且不拥挤。
- 900px 和 560px 断点无内容遮挡、无法操作或页面横向整体溢出。
- 键盘焦点可见，主要交互不依赖纯颜色表达。
- `prefers-reduced-motion` 下关闭非必要动画。
- 现有测试通过，生产构建成功。
- 不改变已有业务结果、API 调用和数据持久化行为；客户端状态页保持现状。

## 12. 风险与控制

- **全局 CSS 回归**：先建立令牌和共享组件，再按页面分批替换；每阶段做截图和测试。
- **大型页面选择器冲突**：复杂页面保留页面命名空间，避免无边界的全局覆盖。
- **桌面/Web 差异**：两种入口分别启动验证，公共样式保持一致。
- **样式文件继续膨胀**：本次不强制拆分所有 CSS，但新增规则按基础、组件、页面、响应式分区，并删除由本次改造产生的重复覆盖。
- **字体环境差异**：使用系统字体栈，不依赖网络下载。

## 13. 成功定义

改造完成后，用户应感受到这是同一个熟悉的 Ozon SJSQ 产品，但具有更统一的品牌表达、更清晰的信息层级、更可靠的交互反馈和更适合桌面端长期运营的视觉质量；同时所有现有业务能力保持可用。
