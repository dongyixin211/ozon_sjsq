# 飞书任务通知与活动保护设计

## 目标

在不改变现有 Tauri 本地助手架构的前提下，实现：

- 用户通过飞书自定义机器人接收本机任务通知；
- 店铺自动运维仅保留类目活动规则允许的活动商品，移除 Ozon 自动加入的其他活动商品；
- 监控店铺商品正常卖价变化，并通过飞书通知。

Ozon 凭证、飞书 Webhook 和飞书签名密钥都只保存于用户 Windows 本地安全存储，不上传云端。

## 范围与非目标

本次只扩展本地助手的配置、任务生命周期、自动运维和 React 设置页面。云端租户、设备配对、SKU 预留和完整 SaaS V2 重构不在本次范围内。

不接入飞书 OAuth 登录、飞书应用、个人消息或云端通知队列。用户自行在飞书群添加自定义机器人，并把机器人 Webhook 配置到本地助手。

## 飞书通知

每名本地用户配置一个飞书机器人：启用开关、Webhook 地址和可选签名密钥。设置页提供测试通知。凭证写入既有 Windows 安全存储，配置模型只暴露“已配置”状态，不回传明文。

在 `JobRegistry` 的统一生命周期边界投递通知，覆盖所有本地任务：

1. 创建任务后发送“开始”通知；
2. 任务进入 `succeeded`、`partial_failed`、`failed` 或 `cancelled` 时发送一条最终结果通知；
3. 一般进度与调试日志只保留在任务中心，不逐条推送；
4. 通知失败只写入任务日志，不影响业务任务；
5. 同一轮内的卖价变动合并为一条通知。

消息包含任务名称、店铺、任务 ID、状态、成功/失败计数、错误摘要，以及活动清理或价格变动的业务摘要。

## 活动保护

店铺继续使用现有的“类目活动规则”配置。每项规则将一个类目映射到一个允许参与的 Ozon 活动；同一店铺可以有多条规则。每轮自动运维从规则中收集所有 `action_id`，作为允许活动集合。

只有活动保护已启用且允许活动集合非空时才执行清理：

1. 查询店铺全部 Ozon 活动；
2. 跳过允许集合中的活动；
3. 对每个不在允许集合中的活动，分页查询已参与商品；
4. 将商品 ID 按 Ozon 接口要求分批移除，直至活动为空；
5. 在任务日志记录活动名称/ID、移除数量和失败摘要，并将结果加入飞书任务结果通知。

清理按活动 ID 判断，不再按商品类目二次推断。这样 Ozon 自动将商品加入未授权活动时，商品会在下一轮被移除，避免额外降价。

## 店铺卖价监控

卖价监控与活动无关。每轮自动运维读取店铺商品价格接口的正常卖价，为每个 `(shop_id, product_id)` 保存本地快照。

- 首次读取或商品首次出现：只建立快照，不发通知；
- 后续卖价与快照不同：记录旧价、新价、商品标识和方向，并在本轮结束后合并发送飞书通知；
- 商品不再返回：删除其快照；
- 价格读取或快照写入失败：本轮记录失败，但不阻止活动清理和其他运维步骤。

## 配置与运行

活动保护和卖价监控复用每店已有自动运维开关与执行间隔（默认五分钟）。本地助手运行且该店铺运维任务已启动时，首轮立即执行，之后按间隔循环。停止任务后不再执行清理、价格检查或任务通知。

## 验收标准

- 用户可保存、测试和停用飞书机器人配置，Webhook 明文不通过前端或云端返回。
- 任意本地任务均有开始和最终状态飞书通知；飞书发送失败不会改变任务结果。
- 启用活动保护且存在类目活动规则时，允许活动中的商品保留，未配置活动中的全部商品会被分页、分批移除。
- 未配置任何允许活动时，不执行自动清理。
- 店铺卖价首次同步不发通知，之后的变化会发出包含旧价与新价的合并通知。
- 相关 Rust 单元测试和前端测试覆盖以上规则。
