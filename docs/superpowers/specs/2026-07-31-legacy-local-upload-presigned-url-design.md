# 旧 Excel 本地上架统一 OSS 上传设计

## 1. 目标

保留旧的 Excel 本地批量上架流程。客户端继续在本地完成 Excel 解析、图片处理、水印和 Ozon 商品提交，但商品图片改为上传到管理员在云端配置的统一对象存储。

客户端不得保存或接收 OSS 长期 `AccessKeySecret`。上传成功、失败和上架结果必须回传云端，以便统计图片占用和用户用量。

## 2. 范围

本期包括：

- 云端按登录用户签发单文件、短有效期的预签名上传 URL。
- 客户端旧 Excel 上架流程使用预签名 URL 上传处理后的图片。
- 客户端上传完成后向云端确认对象信息和图片大小。
- 旧流程的预检查取消店铺级 OSS 必填校验。
- 保留 Ozon 密钥、水印、Excel、SKU 图片匹配和上架后自动处理校验。

本期不包括：

- 将管理员 OSS 长期密钥同步到客户端。
- 修改云图库自动上架流程。
- 迁移或删除历史店铺 OSS 配置。
- 新增另一套商品上架执行器。

## 3. 方案选择

采用预签名上传 URL，而不是下发长期密钥或 STS 临时凭证。

原因：

- 单个 URL 仅允许上传一个受控对象，客户端不拥有可枚举或覆盖其他对象的存储权限。
- 云端可在签发和确认两个阶段分别校验用户、SKU、文件类型、大小与对象路径。
- 兼容现有服务端 S3 兼容存储配置及客户端本地处理模式。

## 4. 数据流

`本地读取 Excel 与图片 → 本地处理水印 → 请求预签名 URL → 客户端直传管理员 OSS → 确认上传并记录用量 → 将统一图片 URL 提交 Ozon → 回传上架结果`

1. 客户端为每个处理后的图片请求云端上传授权，传入 SKU、文件名、内容类型和字节数。
2. 服务端验证会员身份、上传大小和内容类型，生成仅归属当前用户和本次上传的对象键与短时预签名 `PUT` URL。
3. 客户端使用 URL 直接上传图片到 OSS，不保存管理员密钥。
4. 客户端提交确认请求；服务端校验对象存在并记录对象键、文件大小、SKU、用户与最终公网 URL。
5. 客户端将确认后的图片 URL 继续交给现有 Ozon 本地批量上架逻辑。
6. 上架完成后，客户端按现有任务历史同步机制回传成功或失败状态。

## 5. 接口边界

新增两个需要登录和会员权限的云端接口：

- `POST /legacy-listing/uploads/presign`：返回对象键、上传 URL、过期时间和统一公网 URL。
- `POST /legacy-listing/uploads/complete`：确认指定对象已上传，并写入用户图片上传记录。

服务端生成的对象键必须由服务端决定，按用户 ID、SKU、随机请求 ID 隔离。客户端传入的文件名仅用于扩展名和审计显示，不能直接构成对象路径。

客户端只保存短时 URL 到当前运行内存；过期或上传失败时重新申请。服务端拒绝未确认的对象用于上架 URL 返回。

## 6. 客户端修改

旧 `preflight_batch_upload` 不再要求 `shop_with_effective_oss` 成功，因此新用户不会再收到“请先在主店配置 OSS”。

旧 `batch::run_batch_upload` 的图片上传步骤改为调用云端授权与确认接口，替换本地 `AliyunOssClient` 直传。Ozon API Key、店铺水印和其余本地业务逻辑保持不变。

云端地址和登录令牌沿用当前客户端云端会话；没有有效会话时，预检查应明确提示“请登录云端会员账号后使用统一 OSS 上架”。

## 7. 失败处理

- 授权失败、登录失效或会员无效：阻止开始上架，提示登录或续费。
- 预签名 URL 过期或 OSS 上传失败：仅重试该图片的授权与上传，不重新提交已成功的图片。
- 上传确认失败：不把该图片 URL 交给 Ozon；任务记录具体 SKU 和文件名。
- Ozon 提交失败：保留已确认的云端图片记录，任务状态按现有失败逻辑回传；不重复上传图片。

## 8. 验收标准

- 未设置任意店铺 OSS 的新用户可通过旧 Excel 上架预检查。
- 本地上架图片进入管理员统一 OSS，客户端不读取或保存管理员 OSS 长期密钥。
- 未登录或无会员的用户无法获取上传授权。
- 服务端拒绝超过限制、非法内容类型、跨用户对象确认和已过期授权。
- 成功上传后，旧上架流程向 Ozon 使用云端返回的统一图片 URL。
- 上传与上架结果能在云端按用户和 SKU 查询到。
- 现有云图库自动上架测试保持通过。
