# Ozon SJSQ 全功能使用文档设计

**目标：** 基于当前项目实现，提供一套面向实际运营人员与管理员的中文功能说明文档，能够支持用户从首次配置完成到日常运营、订单处理、云端自动上架和问题排查。

## 读者与边界

- **运营人员：** 配置店铺与服务、处理素材、上架商品、维护商品、处理订单、使用云图库和自动上架。
- **管理员：** 管理云端账号、许可证、图库资源、自动上架配额与云端服务。
- **不在本次范围：** 逐行解释源码、替代现有部署/API 参考文档，或描述代码中未暴露给用户的内部实现细节。

## 每项功能的固定说明格式

除纯导航内容外，每个功能按以下顺序编写：

1. **作用与适用场景**：说明解决什么业务问题。
2. **前置条件**：账户、授权、店铺、密钥、目录、模板或数据准备要求。
3. **操作入口**：页面、标签或按钮名称。
4. **操作步骤**：按用户实际点击和填写顺序编号。
5. **系统处理流程**：简明解释调用、任务、文件处理和异步状态，不暴露敏感值。
6. **完成标志与产物**：成功状态、生成的 SKU、任务记录、Excel/PDF 或文件目录。
7. **限制与异常处理**：可预期的失败原因、可恢复操作及验证方法。

## 信息来源与准确性规则

- 功能存在性以 React 页面、Tauri 命令与 Fastify 路由的当前行为为准。
- 操作步骤以页面可见字段、按钮、校验提示和任务状态为准，不虚构后台能力。
- 涉及 Ozon、OSS、AI Provider、百度网盘、云端服务时，仅说明项目实际收集的配置项和代码实现的流程。
- 现有 `docs/user-manual.md` 与 `docs/ozon-operation-guide.md` 用于对照、补充和迁移；新文档不复制与功能无关的技术部署细节。
- 部署、API 和云端运维的深度技术内容改为链接到现有专门文档，避免与 `docs/cloud-api-reference.md`、`docs/aliyun-deploy-runbook.md` 等重复。

## 重点流程：商品上架

商品上架章节必须单独覆盖以下闭环：

1. 配置可用店铺、Ozon API 与图片上传服务。
2. 准备 Excel 商品数据、图片目录和产品模板。
3. 在“发布新品”中选择店铺、Excel、图片目录与模板并配置选项。
4. 校验并创建导入任务，上传图片、构建 Ozon 导入项目并提交。
5. 在任务记录或商品工作台查看导入状态与逐项结果。
6. 如启用上架后处理，等待商品 ID 后执行条码生成、库存补充和促销活动加入。
7. 打开 `batch_upload_results.xlsx` 或等价结果记录，核验货号、SKU、图片数、任务 ID 与错误信息。
8. 根据失败类型补齐数据、图片、模板或授权后重新提交可恢复项。


## 重点流程：套图生成

套图说明区分以下两种实际能力，并分别提供完整操作与结果验收：

### 本地场景套图

1. 准备源图片目录；可按 SKU 文件夹批量处理，或指定单张图片试运行。
2. 选择输出目录和本地模板目录；模板目录按场景 ID 提供底图或资源。
3. 选择所需场景，例如平铺全幅、头巾侧戴、头巾后戴、折叠系结和尺码图。
4. 按需设置输出比例、尺码标识和最大处理数量，然后启动本地场景图任务。
5. 在任务记录查看执行状态，在输出目录核验生成图片；文档说明每个场景、比例或模板资源缺失时的处理方法。

### 云端样机套图

1. 登录云端工作区并确保源素材已上传到图库。
2. 选择图库素材和可用样机模板，发起云端套图任务。
3. 等待云端渲染并在图库中查看套图结果、缩略图、模板名称和生成状态。
4. 明确套图结果与原始图库素材的关系，以及自动上架计划仅应选用合格结果素材的规则。
5. 说明模板不可用、素材不符合要求、云端渲染失败或配额不足时的检查和恢复方式。


## 套图技术原理的文档要求

`02-素材处理与场景图.md` 与 `06-云图库与自动上架.md` 必须增加“套图实现原理”小节，使用面向使用者的语言说明以下内容：

- 套图是基于样机模板的图像合成，而不是 AI 重新生成商品图。
- 模板 JSON 定义场景、画布尺寸、图层、图片替换区域和输出格式；一个模板可输出多个场景成图。
- 商品图会经历裁切、缩放、位置调整；复杂模板还会使用透视/网格或 UV 映射、蒙版、裁剪、羽化和颜色修正，使图案贴合样机表面。
- 阴影、高光与纹理等模板图层通过混合模式叠加，保留原商品图案并模拟材质和光照。
- 云图库套图可由浏览器 Canvas 本地渲染后上传结果，云端服务也可通过 `sharp` 执行等价合成；本地助手还提供 Rust `image` 实现。该段只描述用户可感知的处理方式，不暴露密钥、内部路径或协议细节。
- 成品套图将以独立素材记录进入图库；自动上架计划可引用合格的套图结果，且应避免把已生成的套图再次当作原始素材重复处理。

## 验收标准

- 文档目录的每个文件都能从 `docs/feature-guide/README.md` 到达。
- 前端导航中可见的主要业务模块均有归属，不遗漏桌面端或云端功能。
- 新品上架从配置到结果核验可由新用户独立完成。`n- 本地和云端两种套图均说明模板准备、任务启动、结果位置和失败恢复。
- 每个异步任务型功能均说明状态查看位置与失败后的下一步操作。
- 文档中的页面、功能名称和文件产物均能在当前代码或已有用户文档中找到依据。`n- 套图章节准确区分模板合成与 AI 生图，并说明渲染方式、素材关系与自动上架关联。

## 自检

- 覆盖范围与“所有用户可用功能”的要求一致，按运营工作流而不是代码目录划分。
- 已区分普通运营和管理员能力，避免将敏感配置操作混入常规操作。
- 文档不存在待定项、空白章节或未定义术语。
- Git 命令当前不可用，因此未创建提交；该限制不影响文档设计和后续写作。
