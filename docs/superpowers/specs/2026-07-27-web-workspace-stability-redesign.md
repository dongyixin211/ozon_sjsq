# 浏览器工作台精简与稳定性改造设计

## 背景

Ozon SJSQ 当前包含两个不同职责的运行界面：

- Tauri 客户端是本地助手，负责本机文件、密钥、Ozon 接口调用、任务执行、状态检测和软件更新。
- 浏览器工作台负责订单、店铺、模板、图库、商品上架和任务管理等业务操作。

本轮不把网页端全部业务搬入客户端。客户端继续保持轻量，主要改造对象是浏览器工作台。

## 目标

1. 修复订单状态切换和模板配置恢复的确定性问题。
2. 在不删除功能的前提下，降低导航和页面的信息密度。
3. 统一浏览器工作台的视觉层级和操作反馈。
4. 建立覆盖关键状态、配置持久化和主要交互的无副作用测试。

## 运行边界

### 本地助手客户端

保留以下能力：

- 本地助手运行状态。
- 浏览器工作台连接状态。
- 打开浏览器工作台。
- 软件版本检查与更新。
- 后台承载本机文件、密钥和任务处理。

客户端不增加订单、模板、图库、上架等完整业务页面，仅在必要时统一颜色、间距和状态表达。

### 浏览器工作台

继续承载：

- 首页和运营概览。
- 素材生成、图片上传和图库管理。
- 店铺、商品模板、商品库和上架流程。
- 订单查询、发货准备、物流文件下载。
- 任务记录、授权和低频设置。

## 信息架构

一级导航归并为五个主模块：

1. **首页**：账号、店铺、任务和关键业务状态概览。
2. **素材图片**：素材生成、图片上传、待处理、处理中、已上传、精品图库。
3. **商品上架**：店铺管理、商品模板、商品库、批量上架、库存和活动。
4. **订单物流**：订单查询、状态筛选、备货、原订单文件和物流 PDF 下载。
5. **任务设置**：任务记录、授权密钥、更新与其他低频设置。

原有功能入口不删除。图片状态等连续工作流改为模块内部标签页，避免全部堆叠在左侧导航。

## 页面设计原则

参考淘金出海的视觉语言，但不复制其品牌资源：

- 蓝白主色，浅灰蓝背景。
- 卡片边界轻、圆角统一、留白增大。
- 每页顶部明确页面目的、核心状态和一个主要操作。
- 次要配置放入折叠区域、抽屉或二级标签。
- 状态数字使用独立指标卡，不与数据列表使用同一份筛选结果计算。
- 成功、警告、失败和运行中状态使用统一颜色与文案。
- 桌面端优先，同时保持现有窄屏响应式布局可用。

## 订单状态修复

### 当前问题

点击“等待备货”后再点击“全部”，调用方把空状态转换为 `undefined`。加载函数使用空值合并逻辑回退到旧的 `statusFilter`，因此仍查询等待备货订单。

状态数字当前基于已筛选的 `rows` 计算，切换到单一状态后，其他状态数字也失去完整数据含义。

### 设计

- 明确区分“没有提供覆盖参数”和“明确选择全部状态”。
- 点击“全部”必须向查询层传递明确的空状态，不得回退到旧状态。
- 订单列表数据与状态汇总数据分离：列表按当前筛选加载，状态数字从同一店铺范围的未按状态过滤汇总中计算。
- 状态切换完成后清空已选订单，避免隐藏订单继续处于选中状态。
- 增加快速连续切换保护，旧请求不得覆盖新请求结果。

## 模板配置修复

### 当前问题

商品上架配置由以下数据共同组成：

- 云端商品模板。
- 云端上架偏好。
- 本地 Ozon 模板。
- 云端和本地店铺列表。

这些数据当前并行加载。默认店铺配置可能先生成，随后自动保存；已保存偏好也可能在店铺或模板尚未加载完成时被裁剪或覆盖，从而出现只恢复部分模板、模板下拉项不完整、后续还需重新配置的问题。

### 设计

- 将模板和上架配置恢复改为分阶段初始化：先加载店铺、云端商品模板、本地模板和偏好，再统一合并生成最终配置。
- 初始化完成前禁止自动保存，避免默认值覆盖云端偏好。
- 恢复配置时保留暂时未出现在店铺列表中的配置，待店铺同步完成后再校验，不在首次渲染时删除。
- 保存商品模板成功后，同时更新模板列表和当前店铺配置，并立即保存上架偏好。
- 本地模板选项重新加载后，保留仍然有效的选择；失效选择显示明确提示，不静默清空。
- 模板列表不做固定数量截断，按共享模板、当前店铺模板和其他可用模板分组显示。

## 状态管理原则

- 服务端数据、页面筛选状态和编辑草稿分开管理。
- 数据加载函数必须接收完整查询对象，不隐式读取可能过期的 React 状态。
- 并发请求使用请求序号或取消标记，只允许最新请求写入页面。
- 自动保存必须等待初始化完成，并基于稳定序列化结果去重。
- 页面切换不清除已保存配置，但清除仅属于当前列表的选择状态。

## 无副作用功能审计

### 自动化验证

- TypeScript 类型检查与生产构建。
- 现有前端 Vitest 测试。
- Rust 单元测试和相关 Cargo 检查。
- 服务端路由和数据校验测试。

### 新增回归测试

- 等待备货切换到全部时查询参数为空状态。
- 快速切换状态时旧响应不能覆盖新响应。
- 状态数字不随列表筛选错误缩小。
- 云端偏好晚于店铺列表返回时仍正确恢复模板。
- 店铺列表晚于偏好返回时配置不被删除。
- 初始化完成前不触发自动保存。
- 保存模板后重新进入页面仍恢复商品模板和本地 Ozon 模板。

### 浏览器检查

- 导航和模块标签切换。
- 订单筛选、关键词和店铺筛选。
- 模板选择、保存、刷新和恢复。
- 图片工作流各标签的空状态、加载状态和错误状态。
- 任务列表和详情。
- 常见桌面宽度及窄屏布局。

### 禁止真实执行的操作

除非用户另行明确授权，不真实执行：

- 发布或更新 Ozon 商品。
- 确认发货。
- 删除云端或本地业务数据。
- 调用付费 AI 生成。
- 提交其他不可逆外部操作。

这些操作只验证提交前校验、请求参数和错误反馈。

### 外部系统边界

Ozon、百度网盘、对象存储和付费 AI 等外部系统默认使用模拟响应、契约测试或只读请求验证。不可逆或计费操作不真实执行，但必须验证：

- 提交前参数完整且字段映射正确。
- 重试、超时和错误提示符合预期。
- 外部失败不会错误写入成功状态。
- 部分成功时能够保留准确的逐项结果。

## 数据一致性保证

“数据一致性”通过以下明确不变量进行验证。任何一项不满足都视为阻塞问题。

### 订单一致性

- 状态标签、状态数字和订单列表使用相同的店铺、关键词和时间范围。
- “全部”状态不得继承之前的状态筛选。
- 旧请求响应不得覆盖用户后发起的新筛选结果。
- 已勾选订单必须属于当前可见数据范围；筛选或刷新后失效选择必须清除。
- Ozon 货件编号、订单编号和物流 PDF URL 必须使用独立字段，禁止串位。
- 下载成功、失败数量和数据库下载标记必须与实际逐项结果一致。

### 模板与店铺一致性

- 每个店铺配置使用稳定的店铺 ID，不使用名称作为关联键。
- 商品模板 ID、模板名称和共享范围必须来自同一模板记录。
- 本地 Ozon 模板 ID 必须指向当前本地模板集合中的有效记录。
- 云端偏好保存后再次读取必须得到等价配置。
- 异步加载顺序变化不得造成配置丢失、模板数量减少或默认值覆盖已保存值。
- 店铺同步暂时缺失时保留原配置，确认店铺已删除后才允许清理。

### 图片与上架一致性

- 图片在上传、待处理、处理中、已上传之间只能处于一个有效业务状态。
- 处理任务、源图片、生成图片和上架批次之间的 ID 关联必须可追踪。
- 失败任务不得将图片标记为已上传或已上架。
- 重试不得重复占用额度、重复创建有效批次或重复标记商品已使用。
- 上架模板、店铺、图片规则和标题配置必须在任务创建时形成完整快照。

### 任务一致性

- 任务状态只允许按合法状态机变化，完成或失败任务不得回退为运行中。
- 任务汇总数量必须等于逐项成功、失败和跳过数量之和。
- 本地任务与云端任务历史同步必须保持稳定任务 ID，重复同步应幂等。
- 取消操作必须阻止后续步骤继续写入成功结果。

### 数据库与接口一致性

- 关键写操作使用事务或幂等约束，失败时不得留下半完成关联数据。
- 前后端 Schema、字段命名和可选值保持一致。
- 列表总数、分页结果和筛选条件保持一致。
- 唯一约束、外键和必要索引与业务关联规则一致。
- 迁移脚本可在空数据库顺序执行，并能兼容已有数据升级。

## 测试分层与交付物

### 测试分层

1. **单元测试**：纯函数、筛选、映射、状态机和校验。
2. **组件测试**：标签切换、表单、配置恢复、错误提示和请求参数。
3. **接口与服务测试**：路由 Schema、权限、幂等和数据库读写。
4. **契约测试**：浏览器工作台、本地助手、云端服务和外部 API 之间的数据结构。
5. **构建与静态检查**：TypeScript、Vite、Rust、服务端构建和格式检查。
6. **浏览器冒烟测试**：所有页面入口、主要按钮、空状态、加载状态和错误状态。
7. **一致性场景测试**：刷新、快速切换、重复提交、部分失败、断网恢复和重启恢复。

### 最终测试报告

最终交付时输出一份项目功能审计报告，至少包含：

- 功能模块清单。
- 每项功能的测试方式和结果。
- 新增或补齐的自动化测试。
- 发现并修复的问题。
- 仍存在但不属于本轮范围的问题。
- 因缺少账号、外部权限或禁止副作用而无法真实执行的项目。
- 数据一致性不变量的逐项验证结果。
## 分阶段交付

### 第一阶段：正确性

- 修复订单状态切换和请求竞态。
- 修复模板配置初始化、保存和恢复。
- 增加对应回归测试。

### 第二阶段：结构精简

- 重组五个主模块导航。
- 将连续业务流程迁移为模块内部标签。
- 保持原有页面组件和业务逻辑，避免一次性重写。

### 第三阶段：视觉统一

- 建立颜色、间距、圆角、阴影和状态变量。
- 统一页面标题、指标卡、工具栏、筛选区和列表样式。
- 简化高密度配置区域。

### 第四阶段：功能审计

- 执行全项目自动化测试、构建、接口检查和无副作用浏览器检查。
- 逐项验证订单、模板、图片、任务、数据库与接口的一致性不变量。
- 输出功能审计报告，记录已验证功能、已修复问题和受外部账号限制无法验证的项目。

## 成功标准

- “等待备货 → 全部”稳定显示全部订单。
- 状态数字反映完整订单集合，而不是当前筛选子集。
- 已保存的商品模板和本地 Ozon 模板刷新后仍完整恢复。
- 模板列表不会无故只剩两个，也不要求重复配置。
- 一级导航减少到五个主模块，原有功能均可访问。
- 核心页面有明确主操作，低频设置不再与主流程并列堆叠。
- 新增回归测试先失败后通过，相关构建和测试通过。
- 全项目功能清单都有明确测试结果或无法执行原因。
- 订单、模板、图片、任务、数据库和接口一致性不变量全部通过。
- 所有未能真实验证的外部操作都有明确说明。

## 不在本轮范围

- 不重写 Rust/Tauri 后台任务架构。
- 不把浏览器工作台完整嵌入客户端。
- 不复制淘金出海的 Logo、插画、文案或受保护视觉资产。
- 不进行真实生产上架、发货、删除或付费调用。
