# 用户端改为网页版 + 客户端本地助手方案

## 目标

用户日常操作尽量在浏览器完成，客户端保留为本地助手。

第一版已落地：

- 网页用户工作台：`/app/`
- 会员登录、注册、授权密钥兑换
- 云图库批量上传、分页查询、按比例/货号筛选、图片视图、列表视图、标记已用
- 首页、素材生成、发布商品、更新商品、库存价格活动、订单查询、任务记录、设置页都可以在浏览器打开和操作
- 浏览器通过本机 `http://127.0.0.1:17641/command` 调用客户端本地助手执行本机任务
- 手动同步店铺到云端
- 客户端本地助手健康检查：`http://127.0.0.1:17641/health`
- 桌面端顶部增加“打开浏览器工作台”和“本地助手运行中”提示

## 为什么不能直接全网页化

浏览器不能直接访问用户电脑里的任意 Excel、图片目录、输出目录、HAR/Cookie 文件，也不能安全保存 Ozon Api-Key、OSS Secret 等本地密钥。

如果强行全云端化，会带来这些问题：

- 用户需要上传大量 Excel 和图片，速度和流量成本会上升。
- Ozon Api-Key、Cookie、OSS 密钥集中到服务器，安全责任变大。
- 图片处理、订单 PDF 保存等任务都消耗服务器 CPU、磁盘和带宽。
- 出错时用户无法直接看到本机文件路径和结果目录。

因此推荐混合架构。

## 推荐架构

```text
浏览器用户工作台
  - 账号登录
  - 会员状态
  - 云图库
  - 发布商品/更新商品/库存价格活动/订单查询/素材生成/设置/任务记录
  - 任务结果展示

云后端
  - 会员校验
  - 设备绑定
  - 授权密钥
  - 店铺云端索引
  - 图库文件和使用记录

客户端本地助手
  - 设备指纹
  - 浏览器命令桥
  - 本地文件选择
  - Excel 读取和生成
  - 图片目录处理
  - Ozon API 调用
  - 订单文件下载
  - 本机结果目录打开
```

## 当前访问地址

线上：

```text
用户工作台：https://api.dyxtoolai.cn/app/
管理员后台：https://api.dyxtoolai.cn/admin
云服务状态：https://api.dyxtoolai.cn/
健康检查：https://api.dyxtoolai.cn/health
```

本机客户端启动后：

```text
本地助手：http://127.0.0.1:17641/health
浏览器命令桥：http://127.0.0.1:17641/command
```

## 构建和部署

构建桌面端：

```bash
npm run build
```

构建网页版：

```bash
npm run build:web
```

构建云后端：

```bash
cd server
npm run build
```

部署云后端时，`deploy-cloud-server.ps1` 会先执行 `npm run build:web`，再把 `server` 上传到服务器。

## 后续增强顺序

### P1：助手安全连接增强

- 网页显示连接码。
- 客户端输入或确认连接码。
- 后端或本地助手生成短期 token。
- 本地助手只允许已授权网页调用。

### P2：店铺自动同步增强

- 客户端启动后读取本地店铺。
- 网页登录后触发同步。
- 云端保存店铺基础信息，不保存 Ozon Api-Key 明文。

### P3：任务状态云端同步

- 浏览器展示本机任务实时进度。
- 任务完成后将概要结果同步到云端。
- 用户换浏览器也能看到最近任务摘要。

## 安全注意

- 不要把 R2 Secret、数据库密码、ADMIN_TOKEN、JWT_SECRET 放进前端或客户端。
- 本地助手不要开放任意文件读写接口。
- 本地助手接口必须限制来源；后续增强为一次性连接码。
- 后续建议将云端接口 CORS 从 `origin: true` 收紧到正式域名。
- 服务器 MySQL/PostgreSQL 不应对公网开放。
